# Playbox v0.4 Strategy & Scope Boundaries

Status: **approved (2026-11-19)**.

## 1. Commercial Wedge: Playbox Attested Gate

Playbox `v0.4` pivots external GTM positioning from peer-to-peer developer rooms to **Playbox Attested Gate**:

- **Executable compliance receipts:** cryptographically signed, hash-chained execution & evaluation logs mapped to NIST AI RMF and EU AI Act auditability requirements, backed by hardware attestation tiers (`T1` Secure Enclave/TPM, `T3` Confidential Space TDX) and `libkrun` microVM confinement (`BOX-2`, `BOX-3`, `BOX-6`, `BOX-7`).
- **Anti-reward-hacking evaluation gate:** sealed holdouts, host-owned clocks, dual-host quorum promotion (`RoomLog` + `challenge/room_eval.py` + `challenge/f3`), and sandboxed candidate execution (`challenge/gate.py`).

## 2. Explicit Scope Freezes (`v0.4`)

Product engineering spend is frozen on the following non-wedge areas during `v0.4`:

- `world/`: 3D room visualization.
- `steer/`: cross-family latent telepathy experiments and Swarm channels (kept as reproducible research artifacts, not productized in `v0.4`).
- `desktop/`: cross-platform desktop polish beyond maintaining existing `pbd-core` verification tests.
- Networked `FROST DKG`: interactive threshold keygen / resharing over the network (single-authority `Ed25519` + `RoomLog` epoch handovers remain the supported failover path).

## 3. Post-Quantum & Compliance Profile Boundary

- **Stateless hybrid dual-signing (`ML-DSA-65` / FIPS 204):** `RoomLog` checkpoints (`playbox_core::roomlog`, `playbox_net::roomsync`) and release manifests (`playbox release` / `playbox update`) carry additive stateless `ML-DSA-65` signatures alongside `Ed25519`. Stateful `WOTS+-BLAKE2b` remains confined to `permf` research profiles so operational restarts/failovers never risk state-reuse key compromise.
- **Strict 5-gate compliance claim boundary:** `v0.4` external documentation and compliance receipts claim enforcement **only** for the 5 runtime-native Playbox gates:
  1. **Capability & grant bounds (`GRANT-1..4`, `CAP-1..8`):** Biscuit Datalog attenuation, strict argument validation, pre-run/mid-run revocation checks.
  2. **MicroVM & Linux confinement (`BOX-2..8`):** `libkrun` VM boundary, jail/cgroup/seccomp/nftables isolation, BOX-7 host-side secret-injecting egress proxy.
  3. **Tamper-evident hash-chained logs & receipts (`ROOM-9..17`, `decisions.md` #40):** host-signed `audit.log` and multi-host `RoomLog` checkpoints with hybrid `Ed25519 + ML-DSA-65` cosignatures.
  4. **Sealed anti-Goodhart evaluation gates (`challenge/gate.py`, `challenge/f3`, `room_eval.py`):** sandboxed execution, host-controlled timing, dual-checker / two-host quorum promotion.
  5. **Hardware-bound identity & release integrity (`IDENT-1..8`, `REL-1..9`):** `T1`/`T3` attestation verification and signed `SHA256SUMS` + verified `release.json` manifest updates.
  No claim of `84/84` full-profile runtime enforcement is made in `v0.4`.

## 4. Compliance Bundle Export & Offline Verifier (`playbox gate`)

`playbox gate export` packages verified evidence across the 5 gates (`audit.log`, `roomlog.jsonl`, `BOX-7` egress JSONL, optional `challenge` receipts, and `playbox attest` logs) into a deterministic `playbox.attested_gate.v1` JSON bundle signed with `Ed25519` + `ML-DSA-65` (`--sign-key` / `STATE/endpoint.key`, `--pq-key`). `playbox gate verify` re-checks the canonical digest, signatures, embedded hash chains, egress hygiene, and attestation tier offline (`--require-signature`, `--require-pq`, `--require-tier`, `--json`). External Python `challenge` JSONL entries included without `RoomLog` quorum promotions are explicitly marked `cryptographically_signed: false`.
